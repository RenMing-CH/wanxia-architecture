# 架构说明

## 1. 设计目标

本架构面向长篇小说持续创作场景。它处理的不是一次性摘要，而是章节不断增加后，资料如何形成、审核、更新、追溯，并在后续写作中被可靠引用。

公开架构坚持五个目标：

- **分工：** 复杂任务拆分为边界清晰的阶段。
- **协作：** 多模型按任务需要协作，而非一个模型独自承担全部职责。
- **可审阅：** 模型结果先成为候选，作者审核后才成为正式资料。
- **可追溯：** 资料能够关联来源章节和修订历史。
- **可维护：** 卡片具有稳定身份，支持持续更新、历史查看和回溯修订。

## 2. 三轮提取流程

~~~mermaid
flowchart TD
  A[完整章节输入] --> B[第一轮：类型识别]
  B --> C[第二轮：档案检索]
  C --> D[第三轮：整章分析与全量化输出]
  D --> E[候选卡片集合]
  E --> F[作者审核]
  F -->|接受| G[已批准档案]
  F -->|修改| E
  F -->|拒绝| H[不进入正式档案]
  G --> I[持续更新与版本追溯]
  I --> J[白金作家助手按需引用]
~~~

### 第一轮：类型识别

识别小说题材、章节类型和涉及的资料类别，为后续档案检索提供分类依据。

### 第二轮：档案检索

根据分类结果检索相关的已有档案，整理当前章节可能涉及的人物、地点、道具及其他资料。通过按需检索与裁剪，减少无关档案占用上下文。

### 第三轮：章节分析与全量化输出

结合完整章节、类型识别结果和相关档案，分析当前章节并输出完整的结构化候选卡片集合。

当前采用整章全量化输出，而不是把同一章节拆成多批卡片反复生成。已观察到的优点是结果稳定、格式正确，代价是处理时间相对较长。分批处理可能造成的重复处理、遗漏或跨批次不一致属于待验证风险，不作为已证实结论。

当前实验参考模型组合为 Qwen14B 与 Qwen27B。模型可以替换；具体模型分配、提示词、路由条件、参数和内部协议不在公开范围内。

## 3. 卡片生命周期

~~~mermaid
stateDiagram-v2
  [*] --> Candidate: 模型提出候选
  Candidate --> Review: 作者审核
  Review --> Approved: 作者确认
  Review --> Revised: 作者修改
  Review --> Rejected: 作者拒绝
  Revised --> Review: 再次审核
  Approved --> Maintained: 后续章节持续维护
  Maintained --> Versioned: 形成新版本
  Versioned --> Maintained: 后续继续更新
  Maintained --> Referenced: 工作台按需引用
  Rejected --> [*]
~~~

### 3.1 稳定身份与归属

每张卡片具有稳定身份，并关联明确的人物、地点、道具或其他语义主体。名称变化不应破坏卡片身份；不同对象即使名称相同，也不能仅凭名称合并。

本文件只公开稳定身份和归属原则，不披露内部身份分配规则。

### 3.2 持续更新

后续章节再次涉及已有资料时，优先匹配并更新对应卡片；不存在对应档案时，才建立新卡片。更新应围绕卡片身份和归属执行，避免重复建档或错误覆盖。

### 3.3 作者审核边界

模型输出仅为候选资料。作者可以接受、修改或拒绝。只有作者确认的内容才进入正式档案。

已批准档案是后续工具维护和引用的依据。其他功能不能绕过批准边界，重新读取小说正文并擅自裁定事实。

### 3.4 历史版本与回溯修订

每次正式更新保留版本和来源信息。作者可以查看当前版本、回看历史版本、比较变化，并以旧版本为基础继续修改。

恢复旧版本不应删除中间历史，而应形成新的修订记录。历史保留使作者既能修正过去的资料，又能追溯完整演进过程。

### 3.5 跨模块同步

已批准卡片可以按需同步到数值、地图、时间线、作者手记等工作台模块。同步依据明确的资料身份和版本执行，未确认的模型建议不自动转化为有效事实。

同步失败时，应定位到具体卡片或资料位置，保留可用数据，提供人工处理或重试入口，并记录后台错误信息。

## 4. 作者审核与资料边界

| 参与方 | 主要职责 | 不拥有的权力 |
|---|---|---|
| 作者 | 提供正文、设定目标、审核和决定资料 | 无需接受模型建议 |
| 任务协作层 | 拆分任务、组织阶段协作、传递结果 | 不决定小说事实 |
| 模型阶段 | 在限定任务内提出分析或候选结果 | 不自动批准资料、不直接控制作者作品 |
| 资料工作台 | 展示已确认资料、来源与历史 | 不把未确认建议伪装成正式资料 |
| 世界构建工具 | 帮助作者维护空间、时间、数值和阵营信息 | 不自动裁定剧情或推进世界状态 |

## 5. 白金作家助手模块视图

- **正文编辑区：** 作者创作、查看章节、进行局部标注。
- **资料联动区：** 根据作者操作展示相关资料，减少频繁跳转。
- **作者手记：** 管理批注、提醒和创作想法。
- **数值管理：** 展示数值及来源，要求作者确认数值、单位和主体。
- **世界位面与时间线：** 组织空间、时间、地图、阵营及画布式信息。
- **明暗推演与真相迷雾：** 帮助作者检查人物视角、信息差、线索和真相揭露顺序。
- **返工辅助：** 由作者提供修改要求并决定是否采用修改结果。

## 6. 可靠性原则

- 未经作者审核的候选结果不进入正式资料。
- 正文、模型建议、已确认资料、作者手记和数值参考保持概念区分。
- 不能仅凭文本中出现数字，就把它认定为有效数值。
- 地图和时间线展示作者保存的资料，不替代作者作出剧情裁定。
- 出现不确定信息时，应保留待确认状态，而不是通过猜测补齐。
- 更新和同步失败应可定位、可记录，不得伪装为全部成功。
